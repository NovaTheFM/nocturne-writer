# Производительность пагинации больших рукописей — 3 октября 2026

Этот отчёт дополняет [предыдущее исправление сплит-скрина](PAGINATION_SPLIT_RESIZE_FIX_2026-10-03.md). Прежнее снятие блокировки пересчёта исправило геометрию во время перетаскивания, но обнаружило дорогой полный расчёт на каждом изменении ширины. Здесь оптимизирован сам расчёт, без изменения редактируемого документа и оформления. Версия остаётся **1.2.0**, пагинация по умолчанию **выключена**.

## Причины и изменения

1. Для каждой строки длинного абзаца выполнялся двоичный поиск символа с многочисленными `Range.getBoundingClientRect()`. Теперь прямоугольники строк получаются один раз для текстового узла, а позиция символа уточняется только на границах страниц. Сопоставление оригинальных блоков и измерительной копии выполняется одним проходом.
2. На каждом движении создавалась и удалялась скрытая копия рукописи, вынуждая браузер заново строить её layout. Во время перетаскивания копия сохраняется подключённой; документ, состояние плагинов и настройки проверяются перед повторным использованием. Из копии удалены идентификаторы документов/блоков и признаки редактируемой области; она скрыта, `inert`, не участвует в выборе документа или каретке. После завершения перетаскивания либо отключения пагинации копия удаляется.
3. Обновление сотен фоновых листов перемежало чтение геометрии и запись стилей. Размеры бумаги теперь задаются общими CSS-переменными, прозрачность исчезающих листов считывается заранее. Анимация запускается для видимых листов и соседних страниц; далёкие фоны сразу получают конечное состояние. Видимые длительности, отмена исчезновения, активный лист и reduced-motion сохранены.
4. Обработчик разделителя терял последнее движение между кадрами из-за отдельного кадра для сброса флага. Флаг сбрасывается при начале обработки, следующая обработка использует последнюю позицию мыши. Запросы пагинации объединяются без постоянного переноса уже назначенного кадра. Каретка обновляется после пересчёта актуальных переносов.

Основные файлы: `src/editor/visual-pagination.js`, `src/editor/nocturne-editor.js`, целевые участки `src/main.js`, `src/css/ui.css`. В CSS добавлены эквивалентные правила абзацного отступа для изолированной измерительной области. Структура редактируемых абзацев, JSON, хранение, история, выделение и существующее оформление сохранены. Сетки карточек не изменялись.

Проверки добавлены в `scripts/test-pagination.mjs`, `scripts/benchmark-pagination-resize.mjs`, `scripts/test-pagination-visual.mjs` и общий `scripts/verify-project.mjs`. Изменения записаны в `updates.md`.

## Метод измерения

Исходное состояние — checkpoint `7e77c81`; итоговый production-код — `3ce5e6e`. Базовая версия запущена из отдельного `git archive`, без переключения рабочего дерева. Playwright использует отдельные профили, пользовательская база не затрагивается. Chromium **148.0.7778.96**, headless, viewport **1440 × 900**, обычные анимации включены.

Текст калибруется до **53 страниц в начальном сплит-скрине**. Один абзац содержит **14 667 слов / 84 386 символов**; второй сценарий — **13 200 слов**, по 50 слов в абзаце. Разделитель двигается через доли **0.42, 0.60, 0.48** с удерживаемой кнопкой мыши. На узкой ширине первый документ вырастает до **136 страниц**. Проверяются актуальная высота бумаги, позиции текста в полях и неизменность JSON до отпускания мыши. Время проверок геометрии исключено из интервалов кадров.

`layoutP95Ms` — 95-й процентиль измеренных кадров с расчётом пагинации, включая связанное обновление листов/каретки. `frameP95Ms` — интервалы кадров во время перетаскивания. Это показатели конкретной машины и сценария, а не гарантия 60 FPS. В общий pipeline включён отдельный предел **100 мс** для расчёта в сценарии одного абзаца на 53 страницы.

| Сценарий, 53 начальные страницы | Расчёт p95 до | Расчёт p95 после | Интервал кадров p95 до → после | Чтения Range до → после |
|---|---:|---:|---:|---:|
| Один длинный абзац | 194.1 мс | **54.7 мс** | 166.6 → 66.7 мс | 208 224 → 11 686 |
| Много абзацев | 168.8 мс | **64.2 мс** | 166.6 → 66.7 мс | 158 208 → 12 238 |

Для одного абзаца расчёт стал быстрее примерно в **3.5 раза**, чтений Range стало меньше примерно в **18 раз**. Повторение того же сценария внутри полного pipeline дало **60.9 мс** и прошло предел 100 мс. Замер после отдельных оптимизаций давал 51.5 мс; для итогового сравнения выше взят повторный запуск на окончательном коде, без параллельных сборок и тестов.

Дополнительный стресс-тест **50 000 слов** прошёл проверки полей и JSON: один абзац — 180 начальных страниц, до 464 при сужении, **175.4 мс** расчёт p95; много абзацев — 200 начальных страниц, до 524 при сужении, **333.3 мс**. На таком объёме задержки остаются заметны. Результат для 53 страниц нельзя распространять на рукописи любого размера.

Файлы измерений: `release/qa/pagination-performance/final-baseline-53.json`, `final-53-repeat.json`, `verification.json`, `final-50000.json`. Поле `commit` старых записей обозначает HEAD рабочего дерева на момент запуска; исходники базового замера взяты из `baseline-source`, архива `7e77c81`.

## Проверенные и отклонённые варианты

| Вариант | Решение |
|---|---|
| Ленивый поиск символов только на границах страниц; линейное сопоставление блоков | Оставлен: значительно сокращает чтения Range, сохраняет поля и текст. |
| Сохранение изолированной измерительной области во время drag | Оставлен: браузер повторно использует layout; изменения текста, шрифта, отступа, undo/redo и отключение пагинации проверяются отдельно. |
| Общие размеры фоновых листов и анимация видимой области | Оставлен: сокращает обновления и анимации далёких страниц, не меняет видимые листы. |
| Разбиение редактируемого текста на виртуальные фрагменты и `content-visibility` | Отклонён: выявлены неверные координаты и переносы внутри длинного абзаца. Эти варианты не входят в итоговый код. |
| Удаление обёрток глифов из измерительной копии; `contain:size` оболочки | Отклонены по замерам: ухудшали время расчёта. |
| Подавление ResizeObserver по ширине, сохранённой внутри расчёта | Отклонено: теряло последнюю дробную корректировку ширины после изменения шрифта. Сохранён прежний механизм ResizeObserver. |

## Границы проверки

Открытая пользователем вкладка инкогнито напрямую недоступна инструментам этой сессии. Проверка выполнена на воспроизводимых длинных документах, включая кириллицу, emoji и сплошную строку без пробелов. Скорость зависит от оборудования, шрифта и объёма текста; 60 FPS для любого документа не заявляется. Android проверяется в браузерной touch-эмуляции и по составу APK; физический телефон и установка Windows-installer в систему отдельно не проверялись.
