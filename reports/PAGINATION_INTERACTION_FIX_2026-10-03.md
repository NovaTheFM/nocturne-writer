# Исправление взаимодействия с пагинацией — 3 октября 2026

По скриншоту из буфера обмена воспроизведены выделение промежутка между листами и потеря переноса после удаления на границе. Предыдущие проверки недостаточно проверяли настоящие движения мыши и клавиши: программно установленное выделение не выявило поведение браузерного DOM. Прежняя оценка готовности пагинации была слишком сильной.

Скриншот пользователя сохранён в `release/qa/pagination-clipboard.png`. В исходной реализации реальное выделение через границу листов создавало прямоугольник подсветки высотой **270 px**. После исправления в контрольных браузерном и Electron сценариях подсвечивается только текст: прямоугольники высотой **22 px**, промежуток остаётся свободным.

## Причины и исправления

| Причина | Изменение |
|---|---|
| Перенос был пустым `Decoration.widget` с большой высотой внутри редактируемого DOM. Такой узел попадал в геометрию нативного Range и мог исчезнуть при редактировании. | Перенос оформляется CSS-псевдоэлементом декорации настоящего текста, пустого блока либо отступом блочного разделителя. Отдельного пустого удаляемого узла больше нет. Для Unicode декорация охватывает целую кодовую точку. |
| Прямоугольники подсветки строились по всему Range, включая большой контейнер переноса. | В режиме пагинации измеряются только выбранные части текстовых узлов; после пересчёта обновляются выделение, каретка и существующие подчёркивания словаря. |
| Клик/тап в пустом пространстве браузер связывал с неподходящей DOM-позицией. | Координаты промежутка сопоставляются с границей текста в модели редактора. Каретка использует геометрию настоящего текста. Мобильный long press и работа с ручками выделения используют ту же привязку. |
| Ранний выход из пересчёта сравнивал только список переносов. После удаления декорации список мог оставаться прежним. | Проверяется также фактический `DecorationSet`; потерянная декорация восстанавливается при запланированном пересчёте, без следующего ввода. |
| Перенос последней пустой строки после hard break мог сдвигать целый абзац. | Перенос добавляется после последнего реального hard break; отдельный тест проверяет каждую позицию абзаца у границы листа. |
| Новый фильтр текстовых узлов сначала исключал текст при наличии любого внешнего `contenteditable="false"`. В native-приложении такой контейнер окружает редактируемый Tiptap. | Фильтр исключает служебные виджеты ProseMirror. Сценарий воспроизведён до исправления и проверен в браузере и packaged Electron. |

`ignoreSelection` у widget не делает DOM-узел внешним по отношению к браузерному выделению: эта опция управляет синхронизацией выделения внутри виджета. Семантика проверена по [исходнику ProseMirror](https://raw.githubusercontent.com/ProseMirror/prosemirror-view/master/src/decoration.ts).

Промежутки по-прежнему не входят в модель документа, JSON, сохранённые данные и историю undo/redo. Формат файлов и схема базы не изменены. `autoPaginate: false` остаётся значением по умолчанию, версия остаётся **1.2.0**. Сетки карточек с `1fr`, обычное оформление и существующие анимации листов не перерабатывались; новые зависимости не добавлялись.

## Ограничения

Физический Android и его системная клавиатура не проверялись. Touch и ветка Android custom selection проверены в мобильном Chromium 390×844, native Electron — в скрытом окне с эмуляцией фокуса. Установка NSIS-installer в систему не выполнялась; запуск проверен на упакованном Electron рядом с installer/portable. Строгое сравнение одного PNG остаётся красным по описанному выше отличию четырёх пикселей. Проверки подтверждают перечисленные сценарии, а не отсутствие любых возможных ошибок редактора.
