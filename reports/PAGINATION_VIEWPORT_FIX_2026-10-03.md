# Расчёт видимой области при изменении ширины — 3 октября 2026

Продолжение [предыдущей оптимизации](PAGINATION_PERFORMANCE_FIX_2026-10-03.md). Предыдущий вариант всё ещё пересчитывал всю рукопись при каждом изменении ширины. Кроме задержек, изменение ширины попадало в один кадр, а новые переносы — в следующий: текст успевал оказаться в межстраничном промежутке. Новый тест воспроизвёл этот промежуточный дефект, который проверка только после остановки мыши не обнаруживала.

Версия приложения остаётся **1.2.0**. Пагинация по умолчанию **выключена**.

## Что изменено

- Добавлен `src/editor/viewport-pagination.js`. При перетаскивании измеряется область прокрутки с запасом примерно двух страниц с каждой стороны. У большого абзаца берётся диапазон настоящего текста; у набора отдельных блоков — диапазон блоков. Далёкие участки временно исключаются из browser layout CSS-декорациями; их высоту сохраняют два служебных заполнителя. Это не отдельный предварительный просмотр: видимый текст остаётся в редактируемом DOM.
- `src/editor/visual-pagination.js` использует частичный результат во время drag и полный после отпускания. В измерительной копии сохраняется форматирование вокруг диапазона, включая случай, когда оба конца лежат внутри одного `strong`/`em`. Служебные элементы не включаются в измерение полного документа. При завершении удерживается вертикальное положение читаемого текста.
- `src/editor/nocturne-editor.js` добавляет синхронное применение расчёта, обновление области при прокрутке и раскрытие участка при переходе каретки. Данные частичного расчёта сохраняются при транзакциях выделения. Перед вводом в дальний участок выполняется переход без ожидания CSS smooth-scroll: браузер не вводит символы в скрытую DOM-позицию. Исправлено уничтожение экземпляра при назначенном RAF; кадр отменяется, обработчики и временные области очищаются.
- В `src/main.js` ширина и переносы применяются в одной обработке кадра. Custom caret не измеряет длинный скрытый текст, если курсор находится вне рассчитанного диапазона. Видимая каретка сохраняет обычное поведение.
- В `src/css/ui.css` добавлены только правила временно исключённых участков и служебных заполнителей. Оформление видимых страниц, шрифт, поля, анимации и сетки карточек не переоформлялись.

Сам документ, его абзацы, JSON, сохранение и история не содержат заполнителей и разрывов визуальной пагинации. Временные декорации удаляются после полного расчёта, отключения пагинации и уничтожения редактора.

## Измерения и выбранный вариант

Операция: изменение ширины при удерживаемом разделителе, с обычными анимациями. Показатели: p95 расчёта во время drag, интервалы кадров, чтения Range, размер измеренного текста и сохранение данных/полей. Расчёт после отпускания измеряется отдельно. Тесты выполняются в отдельных профилях, без пользовательской базы.

| Вариант | Результат и решение |
|---|---|
| Прежний полный расчёт на каждом движении | Исходный вариант для сравнения; сохранял правильные поля после остановки, но тест между кадрами обнаружил отставание. |
| Ограниченный диапазон с перестроением по текущей области прокрутки | Выбран: проходят поля между кадрами, полный расчёт после drag, ввод, Unicode и форматирование. |
| Дольше сохранять один диапазон при изменении ширины | Отклонён: на 53 страницах расчёт одного абзаца изменился с 15.5 до 18.2 мс, чтений стало больше; на 50 000 слов улучшение времени было в пределах шума. В итоговом коде этот вариант отсутствует. |

Это измеренный безопасный вариант, не заявление об оптимальности для любых документов.

Повторное сравнение выполнено **последовательно, без параллельных сборок и тестов**. Исходники до изменения взяты из отдельного архива checkpoint `88164b1`, текущий код — `49e7b98`. ## Ограничения

Промежуточное число далёких страниц и их геометрия во время drag являются оценкой. Точные разрывы всего документа возвращаются после отпускания разделителя. Это намеренное разделение локального и полного расчёта, а не сохранение старых разрывов в видимой области.

Текущий быстрый путь поддерживает один большой абзац с форматированием и набор непосредственных текстовых блоков размером до 8000 единиц UTF-16 на блок. Другие структуры используют полный безопасный расчёт; например, несколько отдельных очень больших абзацев пока не имеют ограниченного расчёта внутри каждого абзаца. При непрерывном вводе или изменении настроек во время drag сначала восстанавливается корректная полная раскладка и затем создаётся новая область измерения.

Открытая вкладка инкогнито напрямую недоступна. Проверка проведена на изолированных воспроизводимых документах. Время зависит от устройства, шрифта и браузера; 60 FPS для любого объёма не гарантируется. Физический Android и установка Windows-installer в систему отдельно не проверяются.
