# Единый тестер Nocturne Writer

Запуск всего зарегистрированного набора: `npm run qa` или `node scripts/test-app.mjs`. Дополнительные зависимости не требуются. Существующий `npm test` сохранён; оба запуска используют общий каталог проверок.

```powershell
npm.cmd run qa
npm.cmd run qa:smoke
npm.cmd run qa -- --platform=android
npm.cmd run qa -- --platform=desktop
node scripts/test-app.mjs --list
node scripts/test-app.mjs --only=android-polish,workflow-tools
node scripts/test-app.mjs --seed=12345 --steps=12 --repeat=2
node scripts/test-app.mjs --trace=all
node scripts/test-app.mjs --artifacts=required --native-android=required --android-serial=SERIAL
```

## Что проверяется

- Существующие проверки исходников, модели документов, IndexedDB, защищённых записей, синхронизации и авторизации, резервных копий, словаря, пагинации, её производительности, рабочего процесса, импорта/экспорта, офлайн-ресурсов, платформенных контрактов, настоящего Electron, интерфейса и анимаций.
- Android: пустой проект, импорт и восстановление, нижние вкладки, безопасные отступы, главы и папки, перенос удержанием, настройки, макросы, словарь, автозамена, шрифты, шифрование с перезапуском, база знаний и досье, две области, комментарии и финализация, закладки, локальный анализ, заметки, отмена касания, выделение и его ручки, прокрутка, уменьшение viewport, поворот и композиция ввода.
- Дополнительный независимый маршрут на ПК и телефоне: создание через форму, Unicode и составные символы, вставка/удаление, отмена/повтор, сохранение и перезапуск, изменение и восстановление обычных настроек через их контролы с проверкой IndexedDB, сохранность текста при навигации, создание главы без сети. Основной текст сравнивается с отдельной ожидаемой строкой.
- Шесть профилей полного маршрута: настольные 1440 и 1280 px, Android 320 и 390 px, светлая тема, альбомная ориентация и уменьшение анимаций. Быстрый маршрут использует два профиля.
- Геометрия, горизонтальное переполнение, слишком маленькие сенсорные цели, подписи и повторённые идентификаторы; снимки каждого проверяемого раздела.
- Нативный Android через adb/WebView: установленная debug-сборка, настоящие плагины, размеры, системная клавиатура, ввод в палитру и Back. Отсутствие устройства обозначается как пропуск, приложение не устанавливается и не очищается автоматически.
- Упакованные APK/EXE проверяются при наличии или с обязательным режимом `--artifacts=required`. Старый пакет с несовпадающими исходниками должен дать ошибку.
- Сам тестер: девять проверок ложного успешного статуса, ошибок запуска, журналов, таймаута и завершения процесса, занятого порта, безопасного HTML/JUnit, отпечатка исходников, архивации доказательств, поиска и переноса длинных названий в отчёте.

## Журнал и отчёт

Каждый прогон получает отдельную папку `release/qa/app-tester/<UTC timestamp>/`. Старые результаты не перезаписываются.
Для своего пути используйте `--output=<пустая папка внутри проекта>`; непустой каталог отклоняется, чтобы не смешать результаты разных запусков. Не меняйте исходники во время прогона: изменение обнаружит завершающая проверка `source-integrity`.

- `index.html`: области проверки, статусы, поиск, фильтр, названия и ошибки отдельных сценариев внутри наборов, ссылки на доказательства.
- `results.json`: команды, среда, commit, отпечаток исходников, время, результаты и области.
- `junit.xml`: результат для CI.
- `inventory.json`: объявленные действия, настройки, команды форматирования и методы с исходными файлами/строками.
- `features.json`: какие элементы наблюдались в действиях, какие требуют отдельного сценария.
- В каталогах наборов: `output.log`, `context-*.ndjson`, снимки, списки наблюдаемых функций, отчёты и `context-*-trace.zip` для неуспешных наборов. `--trace=all` сохраняет трассы успешных наборов тоже; `--trace=off` отключает трассировку.

Журнал фиксирует действия, фокус, изменения контролов, клавиатурные команды, отмену жестов, размеры viewport, видимость, навигацию, ошибки JavaScript, консоль, ответы и отказы запросов. Ввод паролей и ключей скрывается, значения этих полей и заголовки запросов не журналируются. Трассы и снимки используют изолированные тестовые профили и могут содержать тестовые данные. Нативный пробник работает с уже установленным приложением; его снимки могут включать видимые данные этого устройства.

Открытие трассы: `npx playwright show-trace <путь к trace.zip>` (установленный Playwright, без загрузки зависимостей). Повторять ошибку следует по команде в HTML-отчёте, используя тот же seed и при необходимости `--only=<набор>`.

## Статусы и ограничения

`PASS` подтверждает конкретные утверждения сценария. `OBSERVED` показывает, что действие встречалось в журнале; наблюдение не подтверждает правильность результата. `NOT_OBSERVED` означает отсутствие записи в телеметрии, а не доказанное отсутствие проверки: вспомогательный метод мог выполняться через другое действие. `NOT_SELECTED` относится к областям вне выбранного набора. Пропуск нативного запуска означает `SKIP`, частичное покрытие — `PARTIAL`, а общий успешный прогон с пропусками — `PASS_WITH_GAPS`.

Коды выхода: 1 — ошибка/таймаут, 2 — отсутствующая обязательная нативная или артефактная проверка, 130 — прерывание. В автоматическом режиме `PASS_WITH_GAPS` может вернуть 0; этот статус нельзя объявлять полной проверкой Android.

Ни один автоматический тест не подтверждает художественное качество оформления или отсутствие всех возможных ошибок. Сравнивайте сохранённые снимки и проходите важные сценарии на настоящем устройстве. Разные Gboard/IME, физический LAN, системные пикеры, Share и разные режимы навигационных панелей требуют соответствующей среды. Реальные платные AI-сервисы не вызываются для доказательства локальной работоспособности.

Пять старых диагностических файлов перечислены отдельно в отчёте: сравнения с историческими визуальными эталонами, устаревшие sound/scroll-пробы с localStorage и инспектор пикселей изображения. Они не выдаются за проверки актуального поведения. Визуальный эталон после изменения дизайна должен быть принят отдельно; автоматически переписывать его для получения PASS нельзя.

## Как расширять

Добавляйте проверку в `scripts/qa/checks.mjs`, указывая ID, команду, области, платформы, режимы, timeout и используемые порты. Сценарий должен возвращать ненулевой код при ошибке и работать в отдельном профиле. Новые проверки не должны обращаться к пользовательскому профилю или скрывать отказ через успешный fallback. `scripts/test-app.mjs` автоматически включит их в общий запуск и отчёт.

Для названий внутренних сценариев задайте `scenarioReport` — путь JSON относительно `release/qa`, или `ownScenarioReport` — относительно `NOCTURNE_QA_DIR`. Поддерживается массив либо объект с `results`; элементы содержат `name` / `kind` / `profile`, `passed` либо `status`, необязательные `error` и `durationMs`. Неуспешный внутренний сценарий делает набор неуспешным даже при ошибочно нулевом коде дочернего процесса.
