# План исправления производительности и устранения визуальных багов (fixme.md)

Данный документ содержит исчерпывающий технический анализ, корневые причины багов и детальный алгоритм устранения проблем с производительностью в Nocturne Writer **с гарантией 100% сохранения визуального оформления, стилей и анимаций**.

---

## 1. Баг: Обрезание карточек сверху и снизу (ховер, перенос, сортировка, анимация)

### Корневая причина:
В [src/css/ui.css](file:///d:/%D0%A1%20%D0%B4%D0%B8%D1%81%D0%BA%D0%B0%20%D0%A1%20%D0%B4%D0%B0%D0%BC%D0%BF%D0%B8%D0%BA/coding/today%20we%20steal%20the%20code%202/src/css/ui.css#L4838-L4839) к сеткам `.character-grid` и `.locations-grid` применено:
```css
.character-grid { display: grid; grid-template-columns: repeat(auto-fill, minmax(220px, 1fr)); gap: 24px; contain: layout paint; }
.locations-grid { display: grid; grid-template-columns: repeat(auto-fill, minmax(280px, 1fr)); gap: 24px; contain: layout paint; }
```
- Значение `contain: paint` превращает контейнер в жесткую область отсечения (clipping box).
- При ховере (`.char-card:hover { transform: translateY(-4px); }`) и появлении неоновой тени `box-shadow` верхняя часть карточки и свечение срезаются границей блока.
- При перетаскивании (SortableJS drag) и FLIP-анимации между рядами карточка выходит за пределы ячейки и её края обрезаются.

### Необходимые исправления:
1. **Удалить `contain: layout paint;`** из `.character-grid` и `.locations-grid` в `src/css/ui.css`.
2. Назначить аппаратное ускорение `will-change: transform;` непосредственно карточкам (`.char-card`, `.loc-card`, `.note-card`).
3. Обеспечить `z-index: 100;` и `overflow: visible;` во время перетаскивания (класс `.sortable-drag` и `.is-flipping`).

## 2. Баг: Лаги сплит-скрина при изменении размера с открытым «жирным» документом

### Корневая причина:
В [src/css/ui.css](file:///d:/%D0%A1%20%D0%B4%D0%B8%D1%81%D0%BA%D0%B0%20%D0%A1%20%D0%B4%D0%B0%D0%BC%D0%BF%D0%B8%D0%BA/coding/today%20we%20steal%20the%20code%202/src/css/ui.css#L1513-L1540):
```css
.workspace-stage[data-mode="split"] .page {
  width: min(794px, calc(100% - 32px));
}
```
- При ширине сплит-панели меньше 826px каждый сдвиг сплит-разделителя `#workspace-divider` на 1 пиксель меняет ширину страницы.
- В документе на 50+ страниц находятся тысячи DOM-узлов ProseMirror. Браузер вынужден 60–120 раз в секунду синхронно пересчитывать перенос строк (word-wrap), кернинг и геометрию всех 50 страниц, вызывая просадку до 10–15 FPS.

### Необходимые исправления:
1. **CSS Virtualization через `content-visibility: auto`**:
   - Для страниц/блоков документа, находящихся вне зоны видимости экрана, задать:
     ```css
     .visual-page-sheet:not(.in-viewport) {
       content-visibility: auto;
       contain-intrinsic-size: 794px 1123px;
     }
     ```
   - Браузер полностью пропускает рендеринг и пересчет переноса строк для невидимых 48 страниц. Ресайз сплит-скрина 50-страничного документа обрабатывается так же мгновенно, как документ из 1 страницы (120 FPS).
2. **Изоляция ресайза**:
   - Во время движения разделителя (`resizing-workspace`) глушить все сторонние слушатели и замеры геометрии до события `pointerup`.

## 3. Баг: Заметные лаги при выделении текста в больших документах

### Корневая причина:
При протягивании мыши для выделения текста параллельно генерируются события `document.addEventListener('selectionchange')` и Tiptap `onSelectionUpdate`.
На каждый микро-сдвиг курсора **синхронно** вызывались:
- `updateActivePageHighlight()`: вызывал `window.getComputedStyle(pageShell)` (тяжелый forced reflow) и в цикле `sheets.forEach` обходил все 50 листов.
- `updateCustomCaret()`: вызывал `range.getBoundingClientRect()`.
- `updateToolbarState()`, `renderReviewToolbarSlot()`, `renderTypoSvgOverlays()`.

Множественные синхронные запросы геометрии вызывали **Layout Thrashing** (множественный принудительный пересчет верстки документа за один кадр).

### Необходимые исправления:
1. **Пакетирование в единый `requestAnimationFrame`**:
   - Слушатели `selectionchange` и `onSelectionUpdate` объединяются в единый координированный RAF-цикл.
   - Во время непрерывного драга мыши обновляется только каретка, а тяжелые панели (тулбар, проверка опечаток, ревью-слоты) обновляются 1 раз по завершении выделения или с дебаунсом.
2. **Кэширование геометрии в `updateActivePageHighlight`**:
   - Убрать `window.getComputedStyle(pageShell)`. Значения ширины и высоты листа брать из кэша.
   - Убрать `sheets.forEach(...)` по всем 50 листам. Переключать класс `.active` точечно только между предыдущим и новым активным листом (`lastActiveSheet !== nextActiveSheet`).

## 4. Баг: Восстановление живой динамической анимации сетки БЗ при ресайзе сплит-скрина

### Корневая причина:
Условие `if (isDragging) return;` в `observeKbGridResize` полностью замораживало анимацию карточек во время движения сплиттера. Карточки не перестраивались на лету, а скачкообразно прыгали только после отпускания мыши.

### Необходимые исправления:
1. **Живой динамический FLIP на базе `FastDOM`**:
   - Разрешить ResizeObserver обрабатывать изменение ширины во время драга сплиттера.
   - Замеры `getBoundingClientRect()` выполнять строго в фазе чтения `fastdom.measure()`.
   - Запускать анимацию перелёта `card.animate()` **только для тех карточек, которые сменили строку (`|dy| > 5px`) или колонку (`|dx| >= 30px`)**.
   - Карточки, которые просто растягиваются в текущем ряду за счет CSS Grid `1fr`, не получают лишних анимаций трансформации.
2. **Результат**: карточки плавно, непрерывно и красиво перелетают на новые строки прямо под пальцем/курсором во время движения сплит-разделителя со стабильными 60–120 FPS.

## 5. Рекомендуемые библиотеки и модули для интеграции

1. **FastDOM** (уже вендорирован в проекте): строгое разделение фаз `measure` и `mutate` для исключения Layout Thrashing.
2. **CSS `content-visibility` API**: встроенная браузерная виртуализация больших DOM-деревьев без нарушения разметки и стилей.
3. **Web Animations API (WAAPI)**: прямой запуск трансформаций на GPU Compositor thread.
